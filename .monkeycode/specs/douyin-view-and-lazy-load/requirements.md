# Requirements Document

## Introduction

为 PicWall Android 客户端新增两项浏览体验升级:

1. **列表懒加载**:图库、发现、我的文件、本地库(收藏/历史)四类双列瀑布流列表,从「一次性构建并请求全部条目」改为「视口虚拟化构建 + 卡片临近视口才请求缩略图」,降低大列表下的内存占用与无效网络请求。
2. **抖音视图**:在图库、发现两个列表的顶栏提供入口,以「竖向全屏、上下滑动、当前项 contain 完整展示」的形态浏览当前列表(沿用列表自身的过滤条件);视频静音自动循环播放、点击开声;右侧提供常驻操作图标(收藏/保存/分享/详情等),上滑至底部自动加载更多。

该功能与现有详情页(DetailPage,横向滑动)、网格自动播放(FeedVideoAutoplay)、本地收藏/历史、系统相册保存(gal)体系协同,不引入新后端接口。

## Glossary

- **列表懒加载**:四类媒体列表把「Wrap 一次性构建全部 item」替换为「双列按行分组 + 行级虚拟化滚动容器」,仅构建视口附近(视口 + 缓存带)的行;卡片仅在自身被构建时请求缩略图。
- **缓存带 (cacheExtent)**:虚拟化滚动容器在视口上下额外预构建的区域宽度;用于平衡「滚动顺畅」与「图片提前量」。
- **媒体卡片**:网格中的单格缩略图(`MediaThumb`),以条目宽高比撑开高度,图片/视频/文档/音频各有展示形态。
- **当前列表**:进入抖音视图时所在列表的筛选语义集合;图库含类型/等级/标签/时间排序过滤,发现含类型过滤。
- **抖音视图**:从图库/发现顶栏入口进入的全屏竖向浏览页(模拟短视频形态),一张/一条媒体占满一屏,上下滑动切换。
- **当前项**:抖音视图当前全屏展示的媒体,收藏/保存/分享/详情等操作作用于当前项。
- **点击开声**:视频以静音自动循环播放;用户点击画面后播放器开启声音,再次点击恢复静音。
- **顶栏入口**:图库页、发现页 AppBar actions 区域的切换按钮(图标 + 文案),点击进入抖音视图。
- **PagedMediaGrid**:图库页当前使用的分页网格容器(仅图库使用),持有分页状态(items/page/total/loadingMore)。
- **四类列表**:图库(`GalleryPage` 内的 `PagedMediaGrid`)、发现(`DiscoverPage`)、我的文件(`MyFilesPage`)、本地库(`LocalGridPage`,收藏/历史两个实例)。

## Requirements

### Requirement 1: 列表虚拟化构建

**User Story:** AS 用户, I want 在浏览大列表时不卡顿不浪费流量, SO THAT 滚动流畅且只加载看得见的内容。

#### Acceptance Criteria

1. WHEN 四类列表渲染媒体条目, 系统 SHALL 采用双列按行分组的虚拟化滚动容器替代 `Wrap` 一次性布局, 仅构建视口及缓存带内的行。
2. WHEN 用户滚动列表, 系统 SHALL 复用同一分页/刷新/空态/错误态逻辑, 滚动位置、下拉刷新、无限加载触发点与现有一致。
3. WHEN 用户滚动经过媒体卡片, 系统 SHALL 保持卡片宽高比撑开与现有双列瀑布流视觉一致, 网格视频格的静音自动播放仲裁(FeedVideoAutoplay)继续按原槽位工作。
4. WHEN 行分组后某一行仅剩单个条目(条目总数为奇数), 系统 SHALL 以单列左对齐占满该行宽度, 不拉伸该条目宽度。

### Requirement 2: 卡片临近视口才请求图片

**User Story:** AS 用户, I want 缩略图只在快到眼前时才下载, SO THAT 避免把整页离屏图片提前拉取。

#### Acceptance Criteria

1. WHEN 媒体卡片进入视口与缓存带范围, 系统 SHALL 构建该卡片并加载其缩略图(图片/视频封面)。
2. WHEN 媒体卡片位于缓存带范围之外, 系统 SHALL 保持该行未构建状态, 不发起缩略图请求。
3. WHEN 卡片因滚动离开视口与缓存带而被回收再滚回, 系统 SHALL 复用 CachedNetworkImage 缓存, 不重复整图下载。
4. WHEN 缓存带宽度不足导致快速滚动出现短暂空白, 系统 SHALL 显示灰色占位底而非错位布局。

### Requirement 3: 图库/发现顶栏抖音视图入口

**User Story:** AS 用户, I want 在图库和发现的顶栏一键切换到抖音形态, SO THAT 可以像刷短视频一样上下翻当前列表。

#### Acceptance Criteria

1. WHEN 图库页有内容且过滤已应用, 系统 SHALL 在图库 AppBar 提供抖音视图切换入口; 进入后浏览的列表沿用当前类型/等级/标签/时间排序过滤条件。
2. WHEN 发现页有内容且类型已选择, 系统 SHALL 在发现 AppBar 提供抖音视图切换入口; 进入后浏览的列表沿用当前类型过滤。
3. WHEN 列表为空或加载失败, 系统 SHALL 禁用对应抖音视图入口。
4. WHEN 用户在抖音视图内操作后返回, 系统 SHALL 回到进入前的列表页, 网格滚动位置与筛选状态保持不变。

### Requirement 4: 抖音视图全屏滑动浏览

**User Story:** AS 用户, I want 在抖音视图里逐屏上下滑动查看当前列表, SO THAT 浏览体验连续沉浸。

#### Acceptance Criteria

1. WHEN 抖音视图展示条目, 系统 SHALL 以竖向全屏一屏一媒体的方式展示当前列表条目, 起始为列表第一条, 上下滑动切换前后条目。
2. WHEN 条目为图片, 系统 SHALL 以 contain 完整展示原图; 条目宽高比与屏幕不一致时, 系统 SHALL 以纯黑背景与渐变信息层适配, 不裁剪主体。
3. WHEN 条目为视频, 系统 SHALL 以 contain 完整播放视频; 当前项视频进入视口后自动静音循环播放, 离开视口停止并释放解码资源。
4. WHEN 非当前项(滑动过渡中可见的相邻屏), 系统 SHALL 以封面图 + 播放提示占位, 不初始化解码器。
5. WHEN 用户上滑接近已加载列表尾部, 系统 SHALL 触发加载更多并追加到列表尾部, 连续滑动可继续翻阅直至全部耗尽或接口无更多返回。
6. WHEN 播放失败(含当前设备解码不支持的编码), 系统 SHALL 走 NativeVideoPlayer 既有软解回退与错误界面逻辑, 与详情页一致。

### Requirement 5: 抖音视图视频声音交互

**User Story:** AS 用户, I want 视频默认无声自动播, 想看声音时点一下就有声, SO THAT 不影响默认浏览体验。

#### Acceptance Criteria

1. WHEN 视频开始自动播放, 系统 SHALL 以静音状态播放。
2. WHEN 用户点击视频画面, 系统 SHALL 切换该视频的声音状态:静音 ↔ 有声, 并更新声音图标指示。
3. WHEN 用户在抖音视图中开启声音后滑动到下一视频, 系统 SHALL 保持用户当前选择的声音开/关状态应用到新视频。
4. WHEN 用户点击图片画面, 系统 SHALL 不切换任何声音状态(图片无声), 且不干扰上下滑动切换。

### Requirement 6: 抖音视图常驻操作栏

**User Story:** AS 用户, I want 在抖音视图右侧直接收藏/保存/分享/查看详情, SO THAT 无需退出即可处理当前项。

#### Acceptance Criteria

1. WHEN 抖音视图展示媒体, 系统 SHALL 在画面右侧提供常驻竖排操作图标, 覆盖: 收藏/取消收藏、保存图片、分享、文件详情; 条目为视频时 SHALL 额外提供「下载视频」。
2. WHEN 用户点击收藏图标, 系统 SHALL 写入/移除本地收藏, 与详情页共用同一收藏存储与去重键, 图标反映收藏态。
3. WHEN 用户点击保存/下载图标, 系统 SHALL 下载原图/原视频并写入系统相册, 权限引导与提示文案与详情页一致。
4. WHEN 用户点击分享图标, 系统 SHALL 分享当前项绝对直链。
5. WHEN 用户点击详情图标, 系统 SHALL 弹出与详情页一致的文件信息底部面板(文件名/类型/尺寸/大小/来源/时间/等级/标签/复制直链)。
6. WHEN 用户在抖音视图浏览当前项, 系统 SHALL 向本地历史写入浏览记录(幂等覆盖), 与详情页行为一致。
7. WHEN 收藏/保存/分享操作失败, 系统 SHALL 展示与详情页一致的失败提示, 且不中断滑动浏览。
