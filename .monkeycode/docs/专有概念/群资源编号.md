# 群资源编号(group_ref)

每条入库消息分配一个「批次-序号」形式的唯一编号(如 `440-001`),用于定位批量转存中的缺失与追溯。

## 1. 编号规则

- 格式:`<批次ID>-<序号>`,如 `440-001`
- **批次**:批内第 1 条以「下一条预计 id」为批次基准,后续消息批内递增
- **新批次判定**:距上一条消息超过 5 分钟视为新批次(`TG_REF_GAP_MS = 300 * 1000`,`worker.js:292`)
- 编号写入 `files.group_ref` 列,同时进入 Bot 回复文本

## 2. 作用

- 用户连续转发大量消息后,对照 Bot 回复即可发现哪条未入库(编号缺失)
- 后台/告警中可用 `group_ref` 定位具体消息
- 不参与内容访问控制(访问控制只由 `level` / `is_private` 决定)

## 3. 相关实现

- 分配:`allocTgRef(env)`(`worker.js:293`)
- 读取:`getFileRef(env, dbId)`(`worker.js:327`)
- 批量预分配:`scheduleBatchRef(env, chatId, dbId, waitFn)`(`worker.js:334`)——批内连续编号预先生成

## 4. 注意

- 批次基准依赖「下一条预计 id」,在并发/乱序入库下序号可能不完全连续
- 该列仅供追溯与展示,不应作为业务主键依赖
