# 签名直链与代理

`GET /file/tg/...` 由 `src/api.js` `handleTgFileRedirect` 处理。不把 Bot token 暴露给客户端。

## 1. URL 格式

| 格式 | 示例 |
|---|---|
| 新（推荐） | `/file/tg/<token>/<id>.jpg` |
| 旧 | `/file/tg/<id>.jpg?k=<token>` |

`fileTok(id, env)` 生成 token。无有效签名返回 403（防枚举）。旧无 token 链接一律拒绝。

## 2. 响应路径

1. 记录存在且未软删
2. `r2_url` 是外部/R2 绝对 URL（不含自身 `/file/tg/`）→ **302**，`Cache-Control: public, max-age=86400`
3. 否则用 `tg_file_url` 或实时 `getFile` 得到 Telegram CDN → **代理流式返回**
4. 代理时透传 `Range`；上游 206 原样转发；上游忽略 Range 回 200 全量时，Worker 按区间切流回 206（否则播放器把整段当偏移，moov 解析失败）

`view_count` 异步 +1。

## 3. 懒转存

`scheduleLazyTransfer`：isolate 内按 id 去重。**带 Range 的请求也触发**（视频播放器总有 Range；旧逻辑 `!rng` 导致视频永不落 R2，叠加冷启动表现为一直加载）。落 R2 后后续访问走 302。

封面：视频条目若无独立缩略图，不要把视频 URL 当 `thumb_url` 再当图片下一次。PicWall 用 `MediaItem.posterUrl` 在缩略图非图片扩展名时返回空。

## 4. 代理模式

`settings.proxy-mode`：入库不写 R2。`proxy-only` 更严。接口 `/admin/api/settings/proxy-mode`、`proxy-only`。
