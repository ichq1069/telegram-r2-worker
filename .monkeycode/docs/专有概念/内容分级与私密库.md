# 内容分级与私密库

内容分级(pt/vip/svip/vvip)是本系统的访问控制核心。它决定「谁(哪个 API 密钥)能看到什么内容」。

## 1. 四级定义与排序

| 级别 | 语义 | 排序 | 后台徽章颜色 |
|---|---|---|---|
| `pt` | 基础级(默认) | 最低 | 灰 |
| `vip` | 会员级 | 低 | 蓝 |
| `svip` | 超级会员级 | 高 | 紫 |
| `vvip` | 最高级(含私密内容) | 最高 | 金 |

代码中的定义(`worker.js` 头部):

- `LEVEL_RANK` / `LEVEL_ORDER`:级别排序表
- `sanitizeLevel(lv)`:非法值一律回落 `pt`
- `levelFilter(keyLevel)`:生成 SQL 过滤片段

## 2. 对等访问规则

密钥级别为 `L` 时,可见 `level <= L` 的公共内容:

```
vvip 密钥 → 可见 pt + vip + svip + vvip(含私密)
svip 密钥 → 可见 pt + vip + svip(不含私密)
vip  密钥 → 可见 pt + vip(不含私密)
pt   密钥 → 仅 pt(不含私密)
```

原则:**低级别输出不得包含高级别内容**。过滤在 SQL 层完成(不拉全量到 Worker 内存)。

## 3. 私密库

- 私密内容 = `is_private = 1`,同时固定 `level = 'vvip'`
- 私密内容**不进入共享库**,仅 `/admin/api/private-pool` 管理
- 访问约束:任何非 `vvip` 密钥的查询都会追加 `is_private = 0` 条件;只有 `vvip` 密钥能拿到私密内容
- 私密内容可来自 Telegram 文件(`/admin/api/private-pool/from-tg`),级别固定 `vvip`

### 私密 vs 高等级

| 维度 | 高等级(vip/svip/vvip) | 私密(is_private=1) |
|---|---|---|
| 入库位置 | 共享库(random_pool) | 私密库 |
| 是否进展示页/轮播 | 不进(展示页仅 pt) | 不进 |
| 可见性 | 级别足够的密钥可见 | 仅 vvip 密钥可见 |
| 管理员入口 | `/admin/api/pool` | `/admin/api/private-pool` |

## 4. 数据落位

内容分级覆盖所有文件类型(图片/视频/文档/音频):

| 表 | 相关列 | 说明 |
|---|---|---|
| `files` | `level TEXT DEFAULT 'pt'`、`is_private INTEGER DEFAULT 0` | 入库文件 |
| `random_pool` | `level TEXT DEFAULT 'pt'`、`is_private INTEGER DEFAULT 0` | 共享/私密库条目 |
| `api_keys` | `level TEXT DEFAULT 'pt'` | 密钥级别 |

默认值均为 `pt`,未分级数据自动按最低级处理,保证存量数据兼容。

## 5. 分级过滤落点

| 场景 | 行为 |
|---|---|
| `/api/v1/files` | 按密钥级别 SQL 过滤 + 非 vvip 追加 `is_private=0` |
| `/api/v1/random` | 同上 |
| `/show/data`(展示页) | 仅取 `level='pt' AND is_private=0` |
| `groupItems` / 节目换图 | 仅取 `pt` 公共内容 |
| 私密库管理 | 仅管理员可达,级别固定 vvip |

## 6. 密钥管理

后台「密钥」tab 可创建/编辑/停用/删除 `api_keys` 记录,创建与编辑时可选级别(pt/vip/svip/vvip)。密钥还支持 `scopes`(默认 `files:read`)、`expires_at` 到期时间、`usage_count`/`last_used_at` 使用统计。非 vvip 密钥即使请求方配置了高等级内容,输出也会被 SQL 层截断。

## 7. 设计决策

- 默认 `pt` 保存量兼容;`sanitizeLevel` 对非法值回落 `pt`
- 级别对等:密钥 L 可见 `level <= L`;私密内容即使级别低也强制仅 vvip 可见(通过 `is_private=1` + 非 vvip 排除实现)
- 私密图片固定 `level='vvip' + is_private=1` 入库;`from-tg` 导入时 `b.level` 未传则继承 `files.level`
- 级别过滤统一在 SQL 层完成,避免把全量数据拉到 Worker 内存再过滤
