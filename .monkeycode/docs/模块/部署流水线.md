# 部署流水线

## Deploy Worker

`.github/workflows/deploy-worker.yml`。`push` `main`，`paths-ignore: android/**`。

```mermaid
flowchart LR
    A["push main"] --> B["node --check"]
    B --> C["npm ci"]
    C --> D["wrangler-action v4 deploy"]
    D --> E["secret put"]
    E --> F["wrangler 4.128.0 二次部署"]
    F --> G["bump-version.js"]
    G --> H["r2 object put --remote"]
```

1. Syntax check：`worker.js` + `src/*.js`
2. `npm ci`（mysql2，打包需要）
3. `cloudflare/wrangler-action@v4`，`wranglerVersion: "4.128.0"`
4. `secret put`：`TG_BOT_TOKEN`、`API_KEY`、`CF_API_TOKEN`（可复用部署 token）、`RELAY_URL` / `RELAY_KEY`（空或旧 HTTP IP 时改写为 `https://botzzxz.wo58.cn`）
5. 二次 deploy（必须 wrangler 4，v3 的 `node:net` 是 stub）
6. 注入 `APP_VERSION`
7. 上传静态页到 R2，**必须 `--remote`**（wrangler 4 默认写本地）

上传对象：`admin.html`、裸 key `admin`、`admin-guide.html`、`user.html`、`user-manage.html`、`jx.html`、`scrape.html`，以及对应无扩展名 key。

## Build Android APK

`.github/workflows/build-android.yml`。`android/picwall_app/**` 或手动 `workflow_dispatch`（可填 version）。

- `flutter create --platforms=android` 脚手架（仓库只留 Dart）
- 注入权限与前台服务
- `flutter analyze` + `flutter test`（info 级失败）
- 用 `github.run_number` 改 `pubspec.yaml` build number；手动输入则改 x.y.z
- release + android-arm64；`ANDROID_DEBUG_KEYSTORE_B64` 确定性重签（v1/v2/v3）
- +62 之前设备是随机签名，需卸载再装

另有 `cleanup-actions-storage.yml`、`gen-keystore.yml`。

## Secrets

| Secret | 说明 |
|---|---|
| `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` | 部署 |
| `TG_BOT_TOKEN` / `API_KEY` | Worker secrets |
| `CF_API_TOKEN` | 可选，R2 用量 |
| `RELAY_URL` / `RELAY_KEY` | 抓取中转 |
| `ANDROID_DEBUG_KEYSTORE_B64` | APK 固定签名 |
| `TG_SECRET` | 未自动部署 |
